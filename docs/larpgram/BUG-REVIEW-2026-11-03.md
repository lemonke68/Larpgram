## Границы проверки

Проверки сервисов используют SQLite в памяти, fake MAS/Matrix/почту либо fake fetch.
Реальные аккаунты, письма, комнаты и серверные ключи тестами не менялись.
На живом Honor не воспроизводились отправки, смена email, восстановление, создание
канала и установка обновления через встроенный PackageInstaller. Android unit/Robolectric-проверки не заменяют эту
приёмку. Публичный канал и доступ новых участников к приватной discussion остаются
в пределах прежних правил членства; опубликованный room ID сам по себе не выдаёт
членство. Для уже существующих старых каналов без общего state остаются legacy
источники; массовая серверная миграция не выполнялась.

Полная сборка требует локальный pinned Rust SDK AAR. Использован уже собранный AAR
из соседнего checkout; `build.py --verify-aar ... --release --all-abis` проверил
provenance и четыре ELF ABI. Пересборка Rust SDK для этих исправлений не нужна.

В checkout тестовые медиа представлены LFS-указателями с отключённым filter.
Объектов нет в LFS форка (404); те же SHA доступны в upstream Element.
Для прогона assets временно гидратированы из upstream, после проверок исходные
указатели восстановлены. Эти двоичные файлы не являются частью исправлений.
